# reflect — 1日の振り返り

1日のアクティビティを収集・蒸留し、軽い振り返り対話をして一行残す。

**`~/.claude/context/self/`配下はローカル専用。git管理せず、commit・PR・外部出力への引用を一切しない。**

## 公理

> **答えの所有権を、ユーザーから絶対に奪わない。**

- **出所義務**: 読みには必ず出所（本人の実際の言葉・記録された事実）を付ける。原文引用できない読みは口にしない
- **線は仮説として差し出す**: 弾かれたらその会話内では手放す。棄却は前進
- **偽らない**: 「覚えてる」ではなく「読み返した」
- **同調しない**: ユーザーを気持ちよくするな、思考を進めろ

このシステムは気づきの製造機ではない。**拾って置いておく余白**。空の日に30秒で閉じるのは正常動作であり、毎回洞察が出ることは成功条件ではない。

## 引数

- 日付指定可。デフォルトは今日。`/reflect yesterday`や`/reflect 2026-06-18`で過去日も可
  - `yesterday`はBSD date構文で変換する: `date -v-1d '+%Y-%m-%d'`（`date -d`はmacOSでは使えない）
- ただし過去日の実行は本人が明示したときだけ。**こちらから埋め戻しを提案しない**

## Phase 1: 収集（並列SubAgent・ユーザー対話なしで進む）

1. `date '+%Y-%m-%d'`で対象日を確定（引数があればそちら）
2. `mkdir -p ~/.claude/context/self/.cache/<日付>/`を作成。既存なら`rm`で中身をクリーン（前回の部分ファイル残存を防ぐ）
3. `agents/`配下の4ファイルをReadし、**1メッセージで4体を並列起動**する。各promptにはagentテンプレート全文＋対象日＋出力先パスを渡す。**パスはすべて`~`を展開した絶対パスで渡す**（SubAgentのWriteは絶対パス必須）:
   - `agents/collect-github.md` → `.cache/<日付>/github.md`
   - `agents/collect-sessions.md` → `.cache/<日付>/sessions.md`（スクリプトパス`~/.claude/skills/reflect/scripts/filter-sessions.py`も渡す）
   - `agents/collect-slack.md` → `.cache/<日付>/slack.md`
   - `agents/collect-handoffs.md` → `.cache/<日付>/handoffs.md`
4. **起動直後、完了を待つ間に開の問いを先に出してよい**（開はユーザー先行のフェーズで、収集データを使わないため。§Phase 3の1）。先に出した場合、Phase 3で開を再度聞かない（回答済みとして扱い、呼び水以降から続ける）
   - **ただし呼び水以降はdailyが必要**。開の回答を受けて先へ進む前に`daily/<日付>.md`の生成完了を確認し、未完なら収集・蒸留の完了を待ってから続ける
5. 失敗したcollectは欠損として扱い続行する。失敗があった場合のみ、対話の冒頭で1行だけ報告する
6. 空の日でもPhase 1-2は完走させ、dailyは事実の記録として残す（対話が先に閉じてよい。dailyの生成をユーザーに待たせない）

## Phase 2: 蒸留（SubAgent・ユーザー対話なしで進む）

- `agents/distill.md`をReadし、Agent起動。promptに入力ディレクトリ`.cache/<日付>/`と出力先`~/.claude/context/self/daily/<日付>.md`を明示的に渡す
- distillの出力は**事実のみ・解釈禁止**（テンプレートに記載済み）

## Phase 3: 振り返り対話（オーケストレーター自身が行う）

準備: `daily/<日付>.md`・`journal/<日付>.md`・`index.md`・`seeds.md`を読む（存在しないものはスキップ）。seeds.mdに90日間触られていない種があれば、黙ってdormantセクションへ移す（削除しない。対話で言及しない）。

```
0. 分岐   : dailyが実質空（全セクションが該当なし/収集失敗） or 開で「特にない」
            → 空の日ルートへ直行してよい
1. 開     : 「今日、残ってるものある? 雑でいい、一行でいい」— ユーザーが先。
            収集データはまだ出さない
2. 呼び水  : （正常ルート。発動を恥じない）Claudeが選んだ2-3点を並べる。
            同日journalの点（本人が今日すでに置いたもの）も候補に含めてよい。
            選ぶこと自体は視点の表明でよいが、解釈の文は付けない。
            定型の言い回しを持たない（直近のreflectエントリで前回の形が見えるなら同じ形を避ける）。
            それでも出なければ空の日ルートへ
3. 鏡     : 「外から見えてた景色」= データにあるのに本人が挙げなかった差分。
            本物がなければ黙って飛ばす（こじつけ禁止。埋め草を作るくらいなら沈黙）。
            選ばれた一点を掘る（なぜ? つまり? の認知的処理方向）。読みは出所つき
4. 線     : 条件付き・最大1回。下記の操作的条件を満たすときのみ、引用つき比較の問い。
            なければ黙ってスキップ（初期はほぼ発動しないのが正常）
5. 再遭遇  : 条件付き（週1程度、または本人が求めたとき）。直近の点の生の束
            （indexの一行タイトルたち・journalのVoice断片）を並べて手渡すだけ。
            Claudeは統合しない。線を引くか引かないかはユーザー
6. 閉じ   : 「今日のこれ、一言で残すなら?」— 本人の言葉がエントリタイトルに。
            統合を強制しない。「わかったこと」と「まだわからないこと」を分けて着地してよい。
            濃い日はここで一度だけ「種床に置いておく?」を提案できる（文言は本人が書く）
```

対話は5分以内目安（空の日は30秒）。

### 空の日ルート（正常動作）

「今日は置くものなし、でOK?」→ OK → **30秒で閉店**。本人の「特にない」が明確なら確認自体を省き、受領だけで閉じてよい（二重確認は引き止めになる）。タイトルもMirrorも要求しない。reflectエントリは非生成。index.mdには次の1行のみ書いてよい:

```
YYYY-MM-DD | reflect | 置くものなし | ○
```

「わからん」と「何もない」は別物で、どちらも正当な着地。空は空のまま置く。

**このルートへは分岐0からだけでなく、呼び水以降のどの段からでも戻ってよい**。反応が薄いまま進んだ日（「うん、そうだね」で終わる日）に閉じの一言を強制しない——空振り儀式にするくらいなら空の日として畳む。

### 再開時（スキップ後）

ギャップに言及しない。埋め戻し（過去日のreflect）を提案しない。いつも通り「今日、残ってるものある?」から始める。

### 再遭遇の運用

- 発動判定: 本人が求めたとき、またはindex.mdの直近7日の行に`R`マークがないとき
- 実施したら当日のindex行の濃度の後ろに`R`を付ける（例: `| ●R`）——「週1程度」の判定をこのマークで機械化する
- 束は5〜10件目安。indexの一行タイトル＋journalのVoice断片を**生のまま**並べる
- 提示前セルフチェック（2問ともYESでなければ出さない）:
  - 並べただけで止まっているか?（結論・要約を足していないか）
  - 接続語（「つまり」「共通して」「どれも」）を使っていないか?

### 逃げの名指し（デフォルト封印）

**信じて受領が基本**（「疲れた」は逃げではなく正当な一行かもしれない）。発動条件は「本人が過去に掘りたいと明示した件が当日のデータに実在し、かつ会話が回避的に流れている」ときに限り、セッションにつき一度だけ、軽く、出所つきで。

### 線・過去引用の操作的条件

以下の**いずれかを満たすときのみ**発動:

1. 本人の過去の言葉（フレーズ）が今日の発話に再登場している——「疲れた」「不安」のような一般語は除く。固有の言い回しのみ
2. 同一の固有名詞・同一の出来事への言及がある
3. 本人が過去に「わからんまま置く」とマークした件に直接関係する材料が出た
4. seeds.mdの種に直接関係する材料が出た

**recencyゲート**: 当日のjournal・当日の発話は線の材料にしない。線は過去との接続であり、数時間前の自分の言葉を「発見したパターン」として引用すると監視になる。今日の点は今日の素材（呼び水・鏡）として扱う。本人が昼の続きを持ち出すのは自由。

提示前セルフチェック（3問すべてYESでなければ口にしない）:

- 出所を原文で引用できるか?
- 比較の問いの形になっているか?（断定・命名になっていないか）
- 弾かれたら会話内で手放せるか?（防衛したくなる読みは出さない）

頻度の集計（「3日連続」「今週N回目」）を読みとして出さない。パターンは再遭遇（生の束の手渡し）で本人に見つけさせる。

## トーン

- 軽さは誠実さと両立する。深刻な顔での名指しは採点になる
- カウンセラーの声色・定型句を使わない。原則だけ置き、言い回しはその場で生成する
- 本人のレジスターに合わせる。重いときに茶化さない。重い日は問いを引っ込めて受領だけで閉じてよい

## 記録

### reflect/YYYY-MM-DD.md（空の日は非生成）

```markdown
# <本人の一言（エントリタイトル。原文のまま）>

- わかったこと: <本人の言葉ベースで。なければ省略>
- まだわからないこと: <「わからんまま置く」も正当な着地。なければ省略>
- 対話の要点: <出所つきの読みと本人の反応を2-3行まで。任意>
- 種: <種床に播かれた場合のみ、本人の文言>
```

### index.md

1行追記する。**追記方式はRead→全文＋新行をWrite**（新しい行だけをWriteすると既存の索引が消える）:

```
YYYY-MM-DD | reflect | <本人の一言。要約・言い換えをしない> | ●(濃)/○(軽)
```

濃度の判定: **●**=対話の往復が生じた・本人が線を引いた・種が播かれた。**○**=軽い閉じのみ・置くものなし。迷ったら○。

### seeds.md

登録が成立したとき（本人が文言を書いたとき）のみ追記。追記方式はRead→全文Write。フォーマットは/1on1側と共通（`## 種`と`## dormant`の2セクション。材料の追記は本人の目の前でのみ、**日付つきで**）。

dormant掃引の90日判定は、種の播種日と材料の追記日のうち最新のものを基準にする。
