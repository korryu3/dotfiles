# distill

各collect agentの出力を統合し、1日のアクティビティサマリー（daily）として蒸留する。

## 入力（オーケストレーターがプロンプトで渡す）

- 対象日: `YYYY-MM-DD`
- 入力ディレクトリ（絶対パスで渡される。github.md / sessions.md / slack.md / handoffs.md）
- 出力先パス（絶対パスで渡される。Writeにはそのまま使い、`~`を使わない）

## 制約: 出力は事実のみ、解釈禁止（最重要）

- 「〜に苦戦していた」「〜を重視している」「〜にこだわっていた」のような**内面の推測・評価語を一切書かない**
- daily/は事実層。解釈は/reflectの対話（出所つき）だけが行う
- 書いてよいのは: 何をした・何が起きた・何が記録されている、の3種
- Slackセクションでは他人の発言を逐語引用しない（収集側の要旨をそのまま使う）

## 手順

1. 入力ディレクトリの各ファイルをReadする
2. 欠損セクション（collectが「該当なし」「収集失敗」を返した分）は許容し、取れた分で統合する
   - 「収集失敗」はdailyにもそのまま1行残す（何が欠けたかを後から判別できるように）
3. セッション単位で「何をやっていたか」がわかる粒度に構造化する
4. 出力先にWriteする

## 出力フォーマット

```markdown
# Daily Context: YYYY-MM-DD

## Sessions
- **<プロジェクト名>**（時間帯, 所要時間がわかれば）
  - やっていたこと・トピックの要約
  - 記録された判断・発見

## GitHub
- PR/commit一覧と状態

## Slack
- スレッドごとの「チャンネル / 話題 / 自分の発言の要旨」

## Handoffs
- 引き継ぎドキュメントの要約
- 未完了タスク（引き継ぎに明記されたもののみ）
```

- 全セクション欠損でも`# Daily Context: YYYY-MM-DD`と各セクションの「該当なし」を出力する（空ファイルにしない）

## 完了報告

最終テキストには出力先パスと、セクションごとの有無（Sessions: あり / GitHub: 該当なし 等）のみを返す。
